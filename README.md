# Magic Upgrade

Flask backend + мини-апп Magic Upgrade + встроенный Telegram-бот (один процесс).

## Запуск

1. Открой `app.py`, найди рамку **«ВСТАВЬ ТОКЕН БОТА СЮДА»** и вставь токен из @BotFather
   в строку `BOT_TOKEN = os.environ.get('BOT_TOKEN') or ''` — между кавычками.
   (Либо задай переменную окружения `BOT_TOKEN` — на Render удобнее так.)
2. `pip install -r requirements.txt`
3. `python app.py`  (на Render start command: `gunicorn app:app`)

Бот стартует вместе с приложением: на `/start` отвечает приветствием и кнопкой
«🎩 Открыть апгрейд», которая открывает мини-апп.

Адрес мини-аппа для кнопки на Render определяется сам (`RENDER_EXTERNAL_URL`).
На другом хостинге задай `WEBAPP_URL=https://твой-домен` (только https).

Не запускай gunicorn с `--preload` — бот стартует в воркере. Воркеров можно
несколько: опрашивать Telegram будет только один.

Переменные окружения (все необязательные): `BOT_TOKEN`, `WEBAPP_URL`, `BOT_USERNAME`,
`POSTSQL`, `DB_PATH`, `DEPOSIT_ADDRESS`, `DEPOSIT_MEMO`.

## База данных

По умолчанию используется SQLite. Если задать переменную окружения **`POSTSQL`**
(строка подключения к Postgres вида `postgresql://user:pass@host:5432/dbname`),
приложение переключится на Postgres автоматически — код сам определяет, что
использовать, ничего больше менять не нужно.

**На Railway** рекомендуется Postgres — это надёжнее, чем файл SQLite в
контейнере, который пересоздаётся при каждом деплое:

1. В проекте Railway: `+ New` → `Database` → `Add PostgreSQL`.
2. Railway создаст сервис Postgres со своей переменной `DATABASE_URL`.
3. В переменных окружения **этого** сервиса (Magic Upgrade) добавь `POSTSQL`
   и укажи значение `${{Postgres.DATABASE_URL}}` (Railway подставит ссылку
   автоматически через reference-переменную) — либо просто скопируй строку
   подключения из вкладки Postgres → Connect.

Если Postgres пока не подключаешь и хочешь остаться на SQLite — данные
переживут рестарт/редеплой только если к сервису подключён **Volume**
(Railway: `Settings` → `Volumes` → `+ New Volume`, точка монтирования любая,
например `/data`). Без Postgres и без Volume файл SQLite неизбежно будет
стираться при каждом новом деплое — так устроена файловая система Railway,
это не лечится настройками самого приложения.

### Ошибка `Name or service not known` (Render)

Если в логах видно что-то вроде:

```
psycopg.OperationalError: failed to resolve host 'dpg-xxxxxxxxxxxxx-a': ...
```

значит в `POSTSQL` вставлен **внутренний (Internal)** connection string
Render — хост вида `dpg-xxxxx-a` без домена резолвится только у сервисов
Render, находящихся в том же регионе, что и сама база. Если приложение
хостится не на Render, в другом регионе, или адрес просто скопирован не
из той вкладки — такой хост не резолвится нигде извне.

Исправление: в Render Dashboard → твоя база Postgres → вкладка
**Connections** → скопировать **External Database URL** (не Internal — у
него хост заканчивается на `...render.com`) и вставить это значение в
переменную `POSTSQL`. После этого пересобрать/перезапустить сервис.

## Админ: ручное пополнение баланса

Telegram-аккаунт с id **5257227756** — встроенный админ по умолчанию.
В профиле у него появляется карточка «Админ» с кнопкой «Получить на
баланс»: по нажатию открывается окно, где можно ввести любую сумму и
подтвердить — она зачисляется на баланс мгновенно, без реального перевода.
Доступ проверяется на сервере по tg_id (эндпоинт `/api/admin/topup`),
поэтому подделать запрос со стороны обычного пользователя не получится.

Чтобы добавить ещё админов, не трогая код, пропиши переменную окружения
`ADMIN_IDS` со списком id через запятую, например:

```
ADMIN_IDS=5257227756,123456789
```

## О сообщении «To use this bot, you must join our channel…»

В этом коде такого текста нет — бот отправляет только `WELCOME_TEXT` из
`app.py`. Если вы видите это сообщение от своего бота, значит на тот же
`BOT_TOKEN` сейчас отвечает какой-то другой процесс/бот (например: токен
случайно попал в другой проект, утёк наружу, или где-то развёрнута вторая,
старая копия сервиса). Рекомендуется:

1. Зайти к **@BotFather** → `/mybots` → выбрать бота → `API Token` → `Revoke
   current token` — это сразу отключит всех, кто пользуется старым токеном.
2. Вставить новый токен в переменную `BOT_TOKEN` здесь и передеплоить.
3. Проверить, что развёрнута только одна копия этого сервиса (не осталось
   старых деплоев/форков с тем же токеном).

## Видео-фон (утро / ночь)

Положи ролики в папку `static/` (можно в подпапку, например `static/bg/`). Сервер раздаёт `/static`
с поддержкой Range (перемотка/потоковая загрузка) и сам находит ролики — список отдаёт `/api/bg`.

**Как назвать файлы** (рекомендуемый вариант):

| Файл                         | Что это                                              |
|------------------------------|------------------------------------------------------|
| `static/bg/day.mp4`          | утро/день (обязательный для дневной темы)            |
| `static/bg/night.mp4`        | ночь (обязательный для ночной темы)                  |
| `day.webm`, `night.webm`     | необязательно: запасной формат для браузеров без H.264 |
| `day-mobile.mp4`, `night-mobile.mp4` | необязательно: облегчённая версия для телефонов |
| `day.jpg`, `night.jpg`       | необязательно: превью, показывается пока грузится ролик |
| `day-1.mp4`, `day-2.mp4` …   | необязательно: несколько роликов — выбирается случайный |

Распознавание идёт по слову в имени, регистр не важен: **утро** = `day`, `morning`, `утро`, `утренний`,
`рассвет`, `sunrise`; **ночь** = `night`, `ночь`, `ночной`, `dark`, `moon`. Подпапки `static/day/` и
`static/night/` тоже работают. Если роликов нет или они не запустились — включается нарисованный фон.

**Как подготовить видео, чтобы не лагало** (ffmpeg, без звука, ~720p, 10–15 с, зацикленное):

```
ffmpeg -i in.mp4 -an -vf "scale=-2:720,fps=30" -c:v libx264 -profile:v main -crf 28 -preset slow -movflags +faststart day.mp4
ffmpeg -i in.mp4 -an -vf "scale=-2:480,fps=24" -c:v libx264 -profile:v main -crf 30 -preset slow -movflags +faststart day-mobile.mp4
```

Положение кадра: по умолчанию `cover` по центру. Сдвинуть — CSS-переменная `--bg-pos` (например
`html { --bg-pos: 50% 70%; }`). Если ролик снят «пеньком под колесом» как старые картинки — включи
`window.BG_VIDEO_ALIGN = true` в блоке «Видео-фон» в `index.html` и подправь `ANCHOR_TALL`.

## Производительность (что сделано)

- Запись БД отложенная (раз в `SAVE_DELAY`=2 с и при остановке процесса), а не после каждого запроса.
- `index.html` отдаётся сжатым (gzip) с ETag/304; `/static/*` — с долгим кэшем по `?v=mtime`.
- Модели подарков: серверная предзагрузка популярных коллекций, явный статус `ready/loading/failed`,
  клиентский опрос с повтором и кнопкой «Повторить».
- Сундуки: без бесконечных анимаций, мгновенный отклик клика, фон-canvas на паузе в этом режиме.
- Режим «Три шляпы» удалён; незавершённые партии при старте возвращаются ставкой на баланс.


## Чтобы сервис не засыпал на Render (keep-alive)

- В `app.py` есть лёгкий маршрут `/healthz` (без БД и блокировок) и фоновый поток, который раз в `KEEPALIVE_SEC` секунд (по умолчанию 540 = 9 минут) обращается к собственному публичному адресу. Адрес берётся из `KEEPALIVE_URL` или автоматически из `RENDER_EXTERNAL_URL`, который Render задаёт сам. Локально, без этих переменных, поток не запускается.
- Бесплатный Render усыпляет сервис после ~15 минут без входящих запросов, поэтому 9 минут достаточно.
- Если сервис всё же уснул (например, после деплоя), самопинг сам не разбудит: добавьте внешний пинг на `https://ВАШ-САЙТ/healthz` раз в 5–10 минут (UptimeRobot, cron-job.org) — это надёжнее всего.
