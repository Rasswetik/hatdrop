# Magic Upgrade

Flask backend + мини-апп Magic Upgrade + встроенный Telegram-бот (один процесс).

## Запуск

1. Задайте `BOT_TOKEN` из @BotFather в переменных окружения хостинга.
2. `pip install -r requirements.txt`
3. `python app.py` (на Render start command: `gunicorn app:app`).

На Render приложение автоматически подключает webhook Telegram после запуска;
публичный адрес определяется через `RENDER_EXTERNAL_URL`. На другом хостинге
задайте `PUBLIC_APP_URL=https://твой-домен`. Приветствие `/start` содержит кнопку
«Играть», открывающую меню. Тексты и кнопки меняются в админке.

`TELEGRAM_WEBHOOK_SECRET` необязателен: если он отсутствует, сервер получает
стабильный 256-битный секрет через HMAC-SHA256 от `BOT_TOKEN` с отдельным
контекстом `hatdrop-telegram-webhook-v1`. Он одинаков у всех воркеров и после
перезапуска. Если переменная задана, используется её значение (1–256 латинских
букв, цифр, дефисов или подчёркиваний). Секрет не возвращается через API.
`ADMIN_SESSION_SECRET` также необязателен: при заданном `BOT_TOKEN` ключ
администраторских сессий получается из него с отдельным контекстом.

Кнопка «Подключить бота» проверяет токен через `getMe`, устанавливает webhook
и проверяет результат через `getWebhookInfo`. Автоподключение сохраняет только
адрес и контрольный хеш, поэтому повторные запуски не меняют рабочий webhook.
При временной недоступности Telegram выполняются повторные попытки.

Переменные: `BOT_TOKEN`, `PUBLIC_APP_URL`, `TELEGRAM_WEBHOOK_SECRET`,
`ADMIN_SESSION_SECRET`, `POSTSQL`, `DB_PATH`, `DEPOSIT_ADDRESS`, `DEPOSIT_MEMO`.

## База данных

По умолчанию используется SQLite. Если задать переменную окружения **`POSTSQL`**
(строка подключения к Postgres вида `postgresql://user:pass@host:5432/dbname`),
приложение переключится на Postgres автоматически — код сам определяет, что
использовать, ничего больше менять не нужно.

**На Railway** рекомендуется Postgres — это надёжнее, чем файл SQLite в
контейнере, который пересоздаётся при каждом деплое:

1. В проекте Railway: `+ New` → `Database` → `Add PostgreSQL`.
2. Railway создаст сервис Postgres со своей переменной `DATABASE_URL`.
3. В переменных окружения **этого** сервиса (Magic Upgrade) добавь `POSTSQL`
   и укажи значение `${{Postgres.DATABASE_URL}}` (Railway подставит ссылку
   автоматически через reference-переменную) — либо просто скопируй строку
   подключения из вкладки Postgres → Connect.

Если Postgres пока не подключаешь и хочешь остаться на SQLite — данные
переживут рестарт/редеплой только если к сервису подключён **Volume**
(Railway: `Settings` → `Volumes` → `+ New Volume`, точка монтирования любая,
например `/data`). Без Postgres и без Volume файл SQLite неизбежно будет
стираться при каждом новом деплое — так устроена файловая система Railway,
это не лечится настройками самого приложения.

### Ошибка `Name or service not known` (Render)

Если в логах видно что-то вроде:

```
psycopg.OperationalError: failed to resolve host 'dpg-xxxxxxxxxxxxx-a': ...
```

значит в `POSTSQL` вставлен **внутренний (Internal)** connection string
Render — хост вида `dpg-xxxxx-a` без домена резолвится только у сервисов
Render, находящихся в том же регионе, что и сама база. Если приложение
хостится не на Render, в другом регионе, или адрес просто скопирован не
из той вкладки — такой хост не резолвится нигде извне.

Исправление: в Render Dashboard → твоя база Postgres → вкладка
**Connections** → скопировать **External Database URL** (не Internal — у
него хост заканчивается на `...render.com`) и вставить это значение в
переменную `POSTSQL`. После этого пересобрать/перезапустить сервис.

## Админ: ручное пополнение баланса

У администратора в профиле доступно ручное пополнение баланса.
Дополнительные аккаунты администраторов задаются переменной окружения `ADMIN_IDS`:
укажи свои Telegram ID через запятую в настройках хостинга.
Проверка доступа выполняется на сервере.

## О сообщении «To use this bot, you must join our channel…»

В этом коде такого текста нет — стандартные сообщения находятся в `bot_messages.py`, а тексты и кнопки
редактируются в админ-панели, в разделе «Telegram-бот». Если вы видите это сообщение от своего бота, значит на тот же
`BOT_TOKEN` сейчас отвечает какой-то другой процесс/бот (например: токен
случайно попал в другой проект, утёк наружу, или где-то развёрнута вторая,
старая копия сервиса). Рекомендуется:

1. Зайти к **@BotFather** → `/mybots` → выбрать бота → `API Token` → `Revoke
   current token` — это сразу отключит всех, кто пользуется старым токеном.
2. Вставить новый токен в переменную `BOT_TOKEN` здесь и передеплоить.
3. Проверить, что развёрнута только одна копия этого сервиса (не осталось
   старых деплоев/форков с тем же токеном).

## Пиксельная SVG-деревня и производительность

Фон встроен в `index.html`: горы, деревня, река, мост, мельница и фонари.
Поведение и оформление находятся в `static/village-scene.js` и `static/village-scene.css`.
Кнопка дня/ночи запускает трёхсекундный закат или восход; ночью появляются луна,
звёзды и свет в окнах и фонарях. Выбор сохраняется в `localStorage`.
Фон не загружает фото или видео и не обращается к `/api/bg`.

- SVG создаётся один раз. Облака, течение реки, дым и мельница используют CSS-анимации;
  постоянного `requestAnimationFrame` и перерисовки canvas для фона нет.
- В скрытом приложении фоновые анимации и опрос состояния приостанавливаются.
  `prefers-reduced-motion` отключает движения и переходы.
- Переход между разделами анимирует только входящий экран, без копирования всей
  сетки инвентаря и элементов игры.
- Изображения подарков масштабирует браузер: нет чтения пикселей и преобразования
  каждого изображения в PNG на главном потоке.
- Запросы состояния объединяются; устаревший ответ не перезаписывает результат
  открытия ячейки. Периодический опрос не выполняется во время активного раунда мин.
- Ячейки мин открываются сразу после ответа сервера, без переворота, вспышек и частиц.
  В интерфейсе мин доступны ставки TON; кнопка ставки подарком и её окно удалены.
  Подарки в составе выигрыша продолжают обрабатываться как раньше.
- Запись БД отложенная (раз в `SAVE_DELAY`=2 с и при остановке процесса).
- `index.html` отдаётся с gzip и ETag/304; статические ресурсы используют версию в URL.
- Модели подарков: серверная предзагрузка, статусы `ready/loading/failed`, повтор загрузки.
- Режим «Три шляпы» удалён; незавершённые партии при старте возвращаются ставкой на баланс.

## Хэллоуин: утро и ночь

Сцена кладбища перерисована по двум референсам: светлое утро и синяя ночь; центральная часть сцены разгружена.
Геометрия `static/halloween-village.svg` встроена в `index.html`; оформление —
`static/halloween-theme.css`. Ночью загораются окна, фонари и подсветка тыкв.
Кнопка переключает обе палитры фона и колеса и сохраняет выбор без блокирующего скримера.
Туман, призраки и летучие мыши используют CSS-анимации; при скрытии приложения
движение останавливается, а `prefers-reduced-motion` отключает анимации.

Сундуки используют три подробных SVG одинакового размера: `mine-closed.svg`,
`mine-candy.svg`, `mine-skeleton.svg`. Во время ивента поле фиолетовое, без цветового фильтра.
Вне ивента используются деревянные `chest-closed.svg`, `chest-gold.svg`,
`chest-empty.svg`. Смена темы обновляет изображения без пересоздания поля
и потери открытых ячеек. Рука скелета доступна только во время ивента; выбор оружия
сохраняется отдельно для обычной и событийной темы.
Класс `cx-revealed` заменяет общий `ghost`, поэтому при проигрыше отступы и размеры
всех 25 ячеек сохраняются. Для оружия используются полный `skeleton-pointer.svg`
и отдельная компактная иконка `skeleton-hand-icon.svg`.

## Чтобы сервис не засыпал на Render (keep-alive)

- В `app.py` есть лёгкий маршрут `/healthz` (без БД и блокировок) и фоновый поток, который раз в `KEEPALIVE_SEC` секунд (по умолчанию 540 = 9 минут) обращается к собственному публичному адресу. Адрес берётся из `KEEPALIVE_URL` или автоматически из `RENDER_EXTERNAL_URL`, который Render задаёт сам. Локально, без этих переменных, поток не запускается.
- Бесплатный Render усыпляет сервис после ~15 минут без входящих запросов, поэтому 9 минут достаточно.
- Если сервис всё же уснул (например, после деплоя), самопинг сам не разбудит: добавьте внешний пинг на `https://ВАШ-САЙТ/healthz` раз в 5–10 минут (UptimeRobot, cron-job.org) — это надёжнее всего.

## Отдельная админ-панель

`/admin` — самостоятельная страница с собственными стилями `static/admin.css`,
полностью тёмной темой, боковым меню на ПК и выдвижным меню на телефоне. Кнопка в профиле игры выдаёт
одноразовый билет на 120 секунд; страница обменивает его на подписанную HttpOnly
сессию на 8 часов. Проверка ADMIN_IDS сохраняется для каждого запроса, cookie-запросы
защищены CSRF. Билет передаётся во фрагменте URL и сразу удаляется из адреса.
На Render cookie Secure включается по HTTPS-адресу `RENDER_EXTERNAL_URL`.
Для других HTTPS-хостингов задайте `SESSION_COOKIE_SECURE=1`; рекомендуется постоянный
`ADMIN_SESSION_SECRET`, особенно если сервер запускает несколько процессов.
Управление пользователями, инвентарём, выводами, промокодами, маркетами, TON Connect
и темой перенесено из модального окна без изменения игровых правил.

Обзор показывает реальные и демо-игры отдельно, периоды сегодня/7/30/90 дней,
ставки, выигрыши, игровой результат, маржу, RTP, графики по дням, текущие балансы,
инвентарь, незавершённые ставки и очередь выводов. Таблица и CSV содержат значения графиков.
Финансовый журнал позволяет вносить операционные доходы/расходы в TON.

`admin_dashboard.py` записывает дневные агрегаты в действующую постоянную БД.
Учёт начинается после обновления; старые усечённые истории без точных выплат
не превращаются в выдуманную прибыль. Игровой результат = ставки − выплаты;
итог = игровой результат + внесённые доходы − расходы. Подарок учитывается по
стоимости в момент выдачи. Незавершённый раунд не учитывается до окончания,
а вывод и продажа уже выданного приза не вычитаются повторно. Этот результат не
равен остатку кошелька или полной бухгалтерской прибыли; пополнения, бонусы,
расходы хостинга и другие операции должны учитываться согласно их реальному назначению.

Проверки: `python -m unittest discover -s tests`.

## Редактор Telegram-бота

В разделе «Telegram-бот» можно менять приветствие `/start`, помощь `/help` и
четыре уведомления о выводах. Для каждого сообщения доступны текст, до восьми
кнопок, их порядок, название, цвет и действие: открыть меню/колесо/мины/профиль
или HTTPS-ссылку. Есть предпросмотр и возврат стандартного сообщения.
Настройки сохраняются в действующей БД (`settings.bot_messages`) и применяются
к новым сообщениям, в том числе после перезапуска. `{name}` и `{gift}` подставляются
однократно, без HTML-разметки.

Стандартное приветствие содержит кнопку «Играть» с `web_app`, открывающую
`?view=menu`. Адрес берётся из настроек TON Connect, затем из
`PUBLIC_APP_URL`/`APP_URL`/`SITE_URL`/`RENDER_EXTERNAL_URL`. Он должен быть HTTPS.
Telegram поддерживает стили `primary` (синий), `success` (зелёный), `danger`
(красный) и стандартный стиль клиента; произвольные HEX-цвета не поддерживаются.
Для подключения приёма `/start` достаточно `BOT_TOKEN` и публичного HTTPS-адреса.
Секрет создаётся автоматически; кнопка «Подключить бота» повторно проверяет подключение.
